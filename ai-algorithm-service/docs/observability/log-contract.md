# Log contract for AI Algorithm Service

## Purpose

This contract defines how AI Algorithm Service emits structured logs for request tracing and operational debugging.

The service must keep working even when the log collector is unavailable. Logging is a side effect, not part of the traffic-control critical path.

## Required fields

Every structured log emitted by the application logger should include:

| Field | Type | Description |
|---|---|---|
| `time` | ISO datetime | Application log timestamp in UTC |
| `level` | string | `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `logger` | string | Logger name, expected `ai_algo_service` |
| `service_name` | string | `ai-runtime`, `ai-ops`, or `ai-algorithm-service` |
| `service_role` | string | `runtime`, `ops`, or `all` |
| `message` | string | Human-readable summary |

Request-scoped logs should also include:

| Field | Type | Description |
|---|---|---|
| `request_id` | string | Trace id from `X-Request-Id` or generated by middleware |
| `event` | string | Structured event/checkpoint name |
| `event_status` | string | `started`, `completed`, `failed`, `skipped`, or `blocked` |

HTTP telemetry logs should include:

| Field | Type | Description |
|---|---|---|
| `http_method` | string | Request method |
| `http_path` | string | URL path |
| `http_status` | integer | Response status code |
| `latency_ms` | integer | Request latency in milliseconds |

Business logs may include:

| Field | Type | Description |
|---|---|---|
| `area_id` | integer | Runtime area id |
| `network_id` | string | Network id |
| `bundle_id` | string | Runtime or sim bundle id |
| `tenant_id` | string | Tenant/customer id |
| `cross_count` | integer | Number of crosses in request |
| `road_count` | integer | Number of roads in snapshot |
| `cycle_count` | integer | Number of cycles in snapshot |
| `stage_count` | integer | Number of stages in snapshot |
| `duration_ms` | integer | Duration of an internal step |
| `trace_step` | string | Short stable step name for Kibana timeline/reporting |
| `error_code` | string | Application error code |
| `error_type` | string | Exception class name |

## Event naming convention

Use dot-separated names:

```text
<domain>.<object_or_step>.<action>
```

Examples:

```text
request.completed
runtime.inference.request_received
runtime.input.validation_completed
runtime.readiness.checked
runtime.policy.loaded
runtime.model.inference_started
runtime.model.inference_completed
runtime.guardrail.applied
ops.real_network.payload_validated
ops.real_network.snapshot_saved
ops.real_network.normalization_compiled
ops.real_network.runtime_notified
ops.real_network.sync_started
ops.real_network.sync_completed
ops.bundle.activate_started
ops.bundle.activate_completed
```

Avoid free-form event names. Add new event names here before using them broadly.

## Current event set

### Request telemetry

| Event | When |
|---|---|
| `request.completed` | Middleware returns a response |
| `request.failed` | Unhandled exception leaves middleware |

### Runtime

| Event | When |
|---|---|
| `runtime.inference.request_received` | `/api/algorithm/ai` accepts a parsed request |
| `runtime.inference.validation_failed` | Input validation failed before inference can run |
| `runtime.input.hydrated` | Compact input has been hydrated with static data |
| `runtime.input.validation_completed` | Input is valid for runtime processing |
| `runtime.area.grouped` | Crosses have been grouped by area |
| `runtime.area.validation_failed` | Multi-area request violates runtime contract |
| `runtime.readiness.checked` | Area readiness has been checked |
| `runtime.inference.area_started` | Per-area inference starts |
| `runtime.policy.loaded` | Area policy/model metadata is loaded |
| `runtime.feature_builder.loaded` | Feature builder is selected |
| `runtime.model.inference_started` | ONNX inference starts |
| `runtime.model.inference_completed` | ONNX inference finishes |
| `runtime.guardrail.applied` | Guardrail changes or flags the proposed plan |
| `runtime.drift.check_failed` | Drift check failed but request continues |
| `runtime.inference.area_completed` | Per-area inference completes |
| `runtime.inference.completed` | Full request inference completes |
| `runtime.inference.failed` | Full request inference fails |

### Ops

| Event | When |
|---|---|
| `ops.real_network.sync_started` | Real network sync starts |
| `ops.real_network.payload_validated` | Snapshot payload passed structural validation |
| `ops.real_network.snapshot_saved` | Snapshot was persisted in the service-owned DB |
| `ops.real_network.normalization_compiled` | `real_normalization.json` was compiled |
| `ops.real_network.normalization_compile_failed` | Normalization compile failed |
| `ops.real_network.runtime_notified` | Runtime reload was notified |
| `ops.real_network.runtime_notify_failed` | Runtime reload notification failed |
| `ops.real_network.sync_completed` | Real network sync completes |
| `ops.real_network.sync_failed` | Real network sync fails |
| `ops.bundle.pull_started` | Runtime bundle pull starts |
| `ops.bundle.pull_completed` | Runtime bundle pull completes |
| `ops.bundle.pull_failed` | Runtime bundle pull fails |
| `ops.sim_bundle.pull_started` | Sim bundle pull starts |
| `ops.sim_bundle.pull_completed` | Sim bundle pull completes |
| `ops.sim_bundle.pull_failed` | Sim bundle pull fails |
| `ops.bundle.register_local_started` | Local bundle registration starts |
| `ops.bundle.register_local_completed` | Local bundle registration completes |
| `ops.bundle.register_local_failed` | Local bundle registration fails |
| `ops.bundle.activate_started` | Bundle activation starts |
| `ops.bundle.activate_completed` | Bundle activation completes |
| `ops.bundle.activate_failed` | Bundle activation fails |
| `ops.bundle.rollback_started` | Rollback starts |
| `ops.bundle.rollback_completed` | Rollback completes |
| `ops.bundle.rollback_failed` | Rollback fails |

## Kibana field mapping

Logstash parses application JSON into `app.*` and promotes selected fields:

| App field | Kibana field |
|---|---|
| `app.request_id` | `request_id` |
| `app.event` | `event.action` |
| `app.event_status` | `event.status` |
| `app.trace_step` | `trace.step` |
| `app.level` | `log.level` |
| `app.service_role` | `service.role` |
| `app.http_method` | `http.request.method` |
| `app.http_path` | `url.path` |
| `app.http_status` | `http.response.status_code` |
| `app.latency_ms` | `event.duration_ms` |
| `app.service_name` | `service.name` when Docker service label is unavailable |

## Recommended Kibana Discover columns

Use a compact trace view instead of reading raw log text:

```text
@timestamp
log.level
service.name
service.role
event.action
event.status
trace.step
request_id
url.path
http.response.status_code
event.duration_ms
event.step_duration_ms
area_id
network_id
bundle_id
error_code
message
```

Filter examples:

```text
request_id : "trace-ai-001"
event.status : "failed"
http.response.status_code >= 500
event.duration_ms > 1000
url.path : "/api/algorithm/ai"
```

The `ai-service-logs` index is intended for structured application trace logs. Raw access logs and noisy probes such as `/metrics`, `/health`, and `/ready` are filtered out before indexing.

## Do not log

Do not log:

- API keys or secrets.
- MinIO access keys or secret keys.
- Full payloads that may be large or sensitive.
- Full model artifacts or binary data.
- Customer credentials or network credentials.

Prefer summaries:

```text
cross_count
road_count
stage_count
area_id
network_id
bundle_id
duration_ms
```
